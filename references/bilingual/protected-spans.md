# Protected Spans

> 本文件是解釋、範例與操作細則；行為合約的單一來源是 `SKILL.md`，兩處表述不一致時以 `SKILL.md` 為準。

> 在追求“更像人”之前，先把不能漂的片段保護住。

這份文檔把 `SKILL.md` 里的 no-touch 原則展開成一個可執行的預檢清單。
`v1.7.0` 先采用 prompt 內 checklist，不要求額外輸出 `facts ledger` 格式。

使用順序：

1. 判場景
2. 先掃一遍 protected spans
3. 再做刪句、并句、換主語、降調
4. 回讀時逐類核對 protected spans 是否還在

## 1. Protect first

先保護，再改寫。預設要先劃出來的內容有：

### 1.1 Numbers, dates, ranges, units

- 數字
- 百分比
- 時間
- 日期
- 版本號
- 區間
- 時間范圍與時間跨度（如“未來十年”“over the next decade”“三個月內”）
- 單位

預設規則：

- 不改數值
- 不隨手四舍五入
- 不把精確說法改成模糊說法
- 不放大、縮小或模糊化時間跨度
- 不補原文沒有的比較項
- 刪除整句時按無源引用規則處理；如果保留相關論斷，不得把原時間跨度改成另一個跨度

### 1.2 Names and attribution

- 人名
- 組織名
- 產品名
- 模塊名
- 服務名
- issue / PR / RFC 編號
- 責任主體和觀點歸屬

預設規則：

- 不換主體
- 不模糊“誰做的 / 誰說的 / 誰負責”
- 不把原來的判斷改成像是別人已經證明過

### 1.3 Quoted text and titles

- 引號內原文
- 引用規范
- 文章標題
- 報告名
- 原話里的關鍵詞

預設規則：

- 引號內容預設原樣保留
- 只在用戶明確要求時改引號內正文
- 不把引用改寫成概述后再塞回引號

### 1.4 Commands, code, params, fields, paths

- 命令
- 程式碼塊
- 接口名
- 參數名
- 字段名
- 配置項
- 文件路徑
- 環境變量

預設規則：

- 拼寫、大小寫、符號、下劃線、連字符都保留
- 不翻譯程式碼語義
- 不把注釋外的技術片段改成人話

### 1.5 Errors, logs, statuses, metrics

- 報錯資訊
- 日志原文
- HTTP 狀態碼
- 指標名
- 實驗結果
- 監控數值
- 結論里的度量關系

預設規則：

- 不換錯誤類型
- 不丟時間范圍、樣本范圍、比較基線
- 不把“觀察到”改成“已經證明”

## 2. What may change around them

protected spans 外面的這些內容通常可以改：

- 開場套話
- 總結式收尾
- 商業黑話
- narrator 腔
- 姿態層
- 空洞判斷包裝

可以做的動作：

- 刪掉 span 前后的廢話
- 調整句序，但不改變事實關系
- 把抽象結論壓回具體動作
- 合并重復句，但不要吞掉保護項

如果一句話只有靠改 protected span 才能變自然，優先保真，寧可保留一點生硬。

## 3. Scene notes

### `status`

重點保護：

- 時間線
- 當前判斷
- 下一步
- 風險歸屬
- 指標和范圍

不要為了更順，把“風險”“阻塞”“未確認”改輕。

### `docs`

重點保護：

- 術語
- 條件
- 順序
- 命令
- 配置
- 系統主語

不要為了口語化犧牲可檢索性。

### `code-context`

重點保護：

- 程式碼本體
- 注釋里描述的真實行為
- 參數
- 返回值
- 約束條件

可以改注釋的 AI 腔，但不能把函數行為改錯。

### `mixed`

重點保護：

- 引用邊界
- 局部場景切換點
- 引號、程式碼塊、復盤塊、公告塊里的原有格式

先判哪里是正文，哪里是引用或嵌入塊，再決定哪些區域能動。

## 4. Worked examples

### A. `status`

原文：

> 昨天把連接池上限從 20 調到 100，504 先壓下來了。后面再觀察 24 小時，如果錯誤率還在 0.1% 以下就全量。

保護項：

- `20`
- `100`
- `504`
- `24 小時`
- `0.1%`

可改部分：

- `先壓下來了`
- `后面再觀察`

### B. `docs`

原文：

> 運行 `bin/migrate --tenant=prod` 后，如果日志出現 `schema mismatch`，先檢查 `DB_SCHEMA_VERSION` 是否和線上一致。

保護項：

- `bin/migrate --tenant=prod`
- `schema mismatch`
- `DB_SCHEMA_VERSION`

可改部分：

- `先檢查`
- 前后解釋層

### C. `mixed`

原文：

> 用戶說“別改我這句，原樣保留”。正文里只要把“值得注意的是”這類套話清掉就行。

保護項：

- `“別改我這句，原樣保留”`

可改部分：

- 引號外的正文說明

## 5. Final check

回讀時至少核對這 5 件事：

1. 數字、日期、單位、版本號有沒有漂
2. 主體、歸屬、責任關系有沒有被換掉
3. 引號、程式碼、命令、路徑、參數有沒有被改壞
4. 錯誤、狀態碼、指標和比較關系有沒有被寫松
5. 有沒有為了“更像人”補進原文沒有的事實、來源或判斷

看不準時，優先保留 protected span，不要賭。
